# myevents.ge — ქორწილების დაგეგმვის პლატფორმა

სტატიკური ვებ-აპლიკაცია (HTML + CSS + JS) Supabase-ის ბექენდით — იმავე პრინციპით,
რითიც `agrointechsol.ge` მუშაობს ამ რეპოში. სერვერული კოდი მხოლოდ SMS proxy-ია (PHP).

## 🚀 დაყენება — 4 ნაბიჯი

### 1. ბაზა
Supabase Dashboard → **SQL Editor** → ჩასვი მთლიანი `sql/myevents.sql` → **Run**.

შეიქმნება:
- 12 ცხრილი `ev_` პრეფიქსით (არსებულ agro-ცხრილებს არ ეხება),
- RLS პოლიტიკები (თითოეული მომხმარებელი მხოლოდ თავის მონაცემს ხედავს),
- საჯარო RPC ფუნქციები RSVP-სთვის,
- storage bucket `myevents` სურათებისთვის.

### 2. Supabase პროექტის მისამართი
ნაგულისხმევად აპი იმავე Supabase პროექტს იყენებს, რასაც agrointechsol.
თუ myevents-ს **ცალკე პროექტი** გინდა, შეცვალე ორ ადგილას:

- `assets/core.js` — ფაილის დასაწყისში `SB_URL` და `SB_KEY`
- `i.html` — სკრიპტის დასაწყისში იგივე ორი ცვლადი
  *(საჯარო გვერდი განზრახ არ იყენებს `core.js`-ს — რომ მოსაწვევი მაქსიმალურად სწრაფად ჩაიტვირთოს)*

### 3. Auth
Supabase → **Authentication → Providers → Email** — ჩართე.
თუ გინდა, რომ რეგისტრაციისთანავე შევიდეს (ელფოსტის დადასტურების გარეშე),
გამორთე *Confirm email*. სხვა შემთხვევაში მომხმარებელი წერილს მიიღებს.

Supabase → **Authentication → URL Configuration** → *Site URL*: `https://myevents.ge`

### 4. SMS (არასავალდებულო, მაგრამ სასურველი)
1. `sms-proxy.php`-ში ჩასვი smsoffice.ge-ის API key (`$API_KEY`).
2. ატვირთე ფაილი `myevents.ge`-ის `public_html`-ში.
3. აპში: **👤 ანგარიში → 📲 SMS პარამეტრები** → Proxy: `/sms-proxy.php`, sender: შენი დარეგისტრირებული სახელი.
4. იქვე გატესტე — „ტესტი" და „ბალანსი".

### ადმინის დანიშვნა
```sql
update public.ev_profiles set role = 'admin'
where user_id = (select id from auth.users where email = 'შენი@ფოსტა.ge');
```
შემდეგ გახსენი `admin.html` და დაადასტურე ვენდორები.

## 🌐 Deploy

`.github/workflows/deploy-myevents.yml` — push-ზე `main` ან `claude/wedding-planning-app-2sja7g`
ბრანჩში ავტომატურად ტვირთავს **მხოლოდ `myevents/`-ის შიგთავსს** საიტის ძირში.

საჭირო secrets (GitHub → Settings → Secrets and variables → Actions):

| Secret | მაგალითი |
|--------|----------|
| `MYEVENTS_FTP_SERVER` | `ftp.myevents.ge` |
| `MYEVENTS_FTP_USERNAME` | cPanel FTP მომხმარებელი |
| `MYEVENTS_FTP_PASSWORD` | პაროლი |

> ⚠️ deploy ყოველ ჯერზე გადააწერს `sms-proxy.php`-ს რეპოს ვერსიით (სადაც key არ არის).
> თუ არ გინდა key-ის ხელახლა ჩასმა — გადაარქვი სერვერზე სხვა სახელი (მაგ. `sms.php`)
> და აპში Proxy-ს მისამართიც შესაბამისად შეცვალე.

## 🔄 როგორ ერწყმის მოდულები ერთმანეთს

```
სტუმრები ──► SMS (პერსონალური ლინკი: i.html?s=slug&g=token)
                     │
                     ▼
              საჯარო მოსაწვევი ──► RSVP პასუხი
                     │                  │
                     ▼                  ▼
             ev_rsvp_log        ev_guests.rsvp განახლდება
                                        │
                                        ▼
                              დასხდომა (მხოლოდ დამდასტურებლები)
                                        │
                                        ▼
                              ბეჭდვადი დასხდომის სია
```

ვენდორები ცალკე ნაკადია: `vendor.html` (რეგისტრაცია + ფოტოები) → `admin.html` (მოდერაცია)
→ `vendors.html` (კატალოგი) → `ev_bookings` (შეკვეთა) → ისევ `vendor.html` (პასუხი + SMS).

## 🔐 უსაფრთხოება

- **RLS ყველა ცხრილზე** — ანონ-key-ით სხვისი სტუმრები/ქორწილი ხელმიუწვდომელია.
- **საჯაროდ იკითხება მხოლოდ:** გამოქვეყნებული მოსაწვევი, დადასტურებული ვენდორები, შეფასებები.
- **RSVP** — `security definer` RPC-ით; ანონიმს ცხრილზე პირდაპირი წვდომა არ აქვს.
- **ვენდორის სტატუსი** — ტრიგერით დაცული: ვენდორი თავად ვერ დაიმტკიცებს თავს.
- **Storage** — ატვირთვა მხოლოდ საკუთარ საქაღალდეში (`myevents/<uid>/...`).
- **SMS API key** — მხოლოდ `sms-proxy.php`-ში, ბრაუზერში არასდროს ჩანს.
